# 자산 현황 (PC 버전)

넓은 PC 화면용 자산 관리 웹앱입니다. **서버도 Supabase도 없이**, 브라우저의
JavaScript가 윈도우 PC의 폴더에 `asset-data.json` 파일을 직접 만들고 읽고 씁니다.
`index.html` 하나를 더블클릭해서 열면 끝입니다.

> 이전 모바일 버전은 Supabase(Postgres)를 DB로 썼습니다. 이 버전은 Supabase 클라이언트,
> 연결 설정, 서비스 워커(PWA)를 모두 걷어냈고, 데이터는 이 PC의 JSON 파일에만 있습니다.

## 구성 파일

| 파일 | 용도 |
|---|---|
| `index.html` | 앱 본체 (HTML + CSS + JS 단일 파일) |
| `icon-192.png` `icon-512.png` `apple-touch-icon.png` | 앱 아이콘 (탭 아이콘은 `icon-192.png`) |
| `.gitignore` | 저장소 폴더를 데이터 폴더로 써도 `asset-data.json`·`backups/` 가 커밋되지 않게 |
| `.github/workflows/pages.yml` | 기본 브랜치에 푸시하면 GitHub Pages로 자동 배포 (`logos.json` 자동 생성) |
| `logos/` | 로고 이미지 폴더 — 웹 주소로 쓸 때 로고가 여기서 나온다 |

## 웹 주소로 열기 — https://iontiger.github.io/asset/

기본 브랜치에 푸시할 때마다 GitHub Actions가 `index.html` 과 아이콘(있으면 `logos/`,
`logos.json` 도)을 GitHub Pages에 올립니다. **처음 한 번만** 저장소
**Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 바꾸고,
**Actions** 탭에서 "Deploy to GitHub Pages" 를 다시 실행(Re-run)하세요.

웹 주소로 열어도 데이터는 GitHub에 올라가지 않습니다. 페이지는 앱 코드만 내려주고,
자산 기록은 여전히 **내 PC에서 고른 폴더의 `asset-data.json`** 에만 저장됩니다.
(`index.html` 을 더블클릭해 여는 것과 웹 주소로 여는 것은 브라우저가 서로 다른 곳으로 보기 때문에,
처음 한 번은 각각 폴더를 골라 줘야 합니다 — 같은 폴더를 고르면 같은 파일을 씁니다.)

## 시작하기

1. `index.html` 을 **Microsoft Edge** 나 **Chrome** 으로 엽니다 (윈도우 기본 브라우저인 Edge면 더블클릭).
2. 처음에는 **데모 데이터**가 보입니다. 모든 화면을 가상의 숫자로 먼저 둘러볼 수 있습니다.
3. 상단 배너나 왼쪽 아래의 **📁 데이터 폴더 연결** 을 누르고 데이터를 둘 폴더를 고릅니다
   (예: `문서\자산`). 브라우저가 "파일 편집 허용"을 물으면 허용합니다.
4. 그 폴더에 `asset-data.json` 이 없으면 새로 만들고, 있으면 그 파일을 불러옵니다.

다음부터 `index.html` 을 열면 같은 폴더를 기억하고 있어서 **"연결"** 버튼만 한 번 누르면 됩니다.
권한 창에서 **"방문할 때마다 허용"** 을 고르면 그마저도 묻지 않고 바로 불러옵니다.

> **권장 배치:** `index.html` 과 아이콘을 데이터 폴더에 함께 넣어 두면 한 폴더로 관리됩니다.
>
> ```
> 📁 문서\자산
>  ├ index.html
>  ├ icon-192.png …
>  ├ asset-data.json      ← 앱이 만든 데이터 파일
>  ├ backups\             ← 하루 한 번 자동 백업
>  └ logos\               ← 로고 이미지 (선택)
> ```

### 브라우저 지원

폴더에 직접 저장하는 기능(File System Access API)은 **Edge · Chrome · Whale 등 Chromium 계열**에서
동작합니다. Firefox·Safari에서는 설정의 **"브라우저에 저장하기"** 로 쓸 수 있지만, 이때 데이터는
그 브라우저 안(localStorage)에만 있으니 **JSON 내보내기**로 따로 백업하세요.

웹폰트(Pretendard, Noto Serif KR, Orbitron)와 코스피·공포탐욕 지수는 인터넷에서 받아옵니다.
오프라인이면 서체는 맑은 고딕으로 대체되고 지수 카드만 빠질 뿐 자산 관리는 그대로 됩니다.

## 데이터 파일 (`asset-data.json`)

메모장으로 열어도 읽기 쉽게, 자산 기록은 한 줄에 하나씩 저장됩니다.

```json
{
  "app": "asset-pc",
  "version": 1,
  "updatedAt": "2026-09-24T02:57:49.610Z",
  "settings": { "goal": 2000000000, "fcMonthly": 5000000, "fcRate": 4, "marks": { "peakNet": 1296427000, "…": "…" } },
  "owners": [
    { "id": "me", "name": "me" },
    { "id": "wife", "name": "wife" }
  ],
  "assets": [
    {"date":"2026-07-12","name":"주식계좌","amount":131968000,"group":"증권","owner":"me","logo":"kb.png"},
    {"date":"2026-07-12","name":"주택담보대출","amount":260000000,"group":"부채>부동산","owner":"me","logo":""}
  ]
}
```

- `assets` 는 **날짜 + 이름**이 같으면 하나로 취급합니다 (같은 날 다시 저장하면 덮어씀).
- `owner` 는 `owners[].id` 를 가리킵니다. 이름을 바꿀 땐 `id` 가 아니라 `name` 만 바꾸세요.
- 부채는 잔액을 양수로 적고 `group` 을 `부채>연동그룹` 형태로 씁니다.
- `pension` 에는 연금 리밸런싱 포트폴리오(종목 · 목표비중 · 보유수량 · 예수금 · 규칙 · 기록)가 저장됩니다.
- `settings` 에는 목표 자산(`goal`), 미래 예상의 월 적립액(`fcMonthly`)과 연 수익률 %(`fcRate`)가 저장됩니다.
- **직접 고쳐도 됩니다.** 앱 창으로 돌아오면 파일이 바뀐 것을 알아채고 다시 불러옵니다.
  JSON 형식이 깨졌으면 앱이 파일을 **덮어쓰지 않고** 오류를 알려 줍니다 — 고치거나
  `backups` 의 파일로 바꾼 뒤 "다시 불러오기"를 누르세요.

### 자동 백업

그날 처음 저장하기 **직전의** 파일을 `backups\asset-data-YYYY-MM-DD.json` 으로 복사합니다.
최근 30개만 남기고 오래된 것은 지웁니다. 되돌리려면 원하는 백업 파일을 `asset-data.json` 으로
복사해 넣고 앱에서 "다시 불러오기"를 누르면 됩니다.

## PC 여러 대에서 쓰기 — 동기화 폴더 (설정 필요 없음)

데이터 폴더를 **OneDrive**(윈도우 기본) · **Google Drive 데스크톱** · **Dropbox** 폴더 안에 두면
`asset-data.json` 과 `backups` 가 자동으로 동기화됩니다.

1. 동기화 폴더 안에 폴더를 만들고 (예: `OneDrive\자산현황`) **📁 폴더 선택**으로 고릅니다.
2. 다른 PC에서도 같은 폴더를 고르면 같은 기록을 봅니다. 다른 곳에서 파일이 바뀌면 창으로 돌아올 때 자동으로 다시 불러옵니다.

- **PC끼리만** 됩니다 (휴대폰 브라우저는 폴더 저장 미지원 — 휴대폰도 쓰려면 아래 클라우드 연동).
- 두 PC에서 동시에 고치지 마세요. 동기화 앱이 `asset-data-PC이름.json` 같은 충돌 사본을 만들면 맞는 쪽을 남기고 지우세요.
- OneDrive는 그 폴더를 "이 디바이스에 항상 유지"로 두면 오프라인에서도 바로 열립니다.
- 앱의 **설정 → 클라우드 연동 → PC 파일** 탭과 사용법(`?`) **클라우드 연동** 탭에도 같은 안내가 있습니다.

## 클라우드 연동 (선택) — Supabase 또는 Google Sheet

기본은 PC 폴더의 JSON 파일이지만, 휴대폰 · 다른 PC 에서도 같은 기록을 보려면 **⚙ 설정 → 클라우드 연동**에서
**Supabase** 나 **Google Sheet** 중 **한 곳**을 저장소로 바꿀 수 있습니다 (둘을 동시에 쓸 수는 없음).

| | Supabase | Google Sheet |
|---|---|---|
| 준비 | 무료 프로젝트 → **SQL 복사** 버튼으로 복사한 SQL 을 SQL Editor 에서 Run | 새 시트 → 확장 프로그램 → Apps Script 에 **Apps Script 복사** 버튼으로 복사한 코드 붙여넣기 → 웹 앱으로 배포(액세스: 모든 사용자) |
| 앱에 넣을 값 | Project URL · anon(publishable) 키 | 웹 앱 URL(…/exec) · 비밀 토큰(스크립트의 `TOKEN`, 권장) |
| 저장 방식 | 바뀐 행만 보냄 (`owners` · `assets` · `app_state` 테이블) | 저장할 때마다 시트 전체를 다시 씀 (`assets` · `owners` · `state` 탭) |
| 특징 | 빠름. **예전 모바일 버전 프로젝트를 그대로 연결 가능** (SQL 은 여러 번 실행해도 안전) | 구글 계정만 있으면 됨. 시트에서 기록을 바로 볼 수 있음 |

- **예전 모바일 버전 Supabase 프로젝트**(owners · assets 테이블만)는 SQL 을 실행하지 않아도 그대로 연결됩니다.
  자산 기록 · 소유자는 Supabase 에, 목표 · 뱃지 · 연금 포트폴리오는 그 브라우저에 저장됩니다
  (SQL 을 실행해 `app_state` 를 만들면 이것들도 Supabase 에 함께 저장). 다른 기기의 변경은 기록 개수로 알아챕니다.
- **예전 Apps Script 웹 앱**은 형식이 달라 바로 저장할 수는 없지만, 연결을 누르면 기록을 찾아 **지금 저장소로 한 번 가져오기**를 할 수 있습니다.
  계속 그 시트에 저장하려면 같은 Apps Script 프로젝트에 **Apps Script 복사** 코드를 붙여넣고
  **배포 관리 → 기존 배포 수정 → 새 버전**으로 배포하세요 — URL 이 그대로이고, 새 코드가 예전 탭(날짜 · 이름 · 금액 머리글)의 기록도 읽습니다.
- **연결**을 누르면 먼저 읽어 봅니다. 클라우드가 비어 있으면 지금 기록을 올릴지 묻고, 기록이 있으면 그걸 불러와 씁니다.
- 연결한 뒤에는 모든 저장이 클라우드로 갑니다. PC 파일은 그대로 남고, **연동 해제**하면 원래 쓰던 PC 방식(폴더 · 브라우저)으로 돌아옵니다.
- 다른 기기에서 먼저 저장했으면 덮어쓰지 않고 최신 기록을 다시 불러옵니다. 창으로 돌아올 때도 바뀐 게 있으면 새로 불러옵니다.
- 주소 · 키 · 토큰은 **이 브라우저에만** 저장되고 코드나 GitHub 에는 올라가지 않습니다. 그 값을 아는 사람은 기록을 읽고 쓸 수 있으니 공유하지 마세요.
- 자세한 순서는 앱의 **사용법 → 클라우드 연동** 탭(`?` 키)에도 있습니다.

## Supabase에서 옮겨오기 (CSV)

위 클라우드 연동으로 예전 Supabase 프로젝트를 바로 연결할 수도 있고, PC 파일로 가져오려면:

1. Supabase 대시보드 → **Table Editor** 에서 `assets` 와 `owners` 테이블을 각각 **Export → CSV** 로 받습니다.
2. 앱에서 데이터 폴더를 연결한 뒤 **⚙ 설정 → ⬆ 가져오기** 에서 두 CSV를 함께 고릅니다.

`asset_group`·`owner_id` 같은 Supabase 열 이름을 그대로 알아듣고, `owners` 는 `sort_order` 순서를
지킵니다. 가져오기는 **합치기**라서 같은 날짜·이름의 기록은 가져온 값으로 덮어쓰고 나머지는 남깁니다.
이 앱에서 내보낸 JSON이나, 기록 배열만 담긴 JSON도 같은 방법으로 가져올 수 있습니다.

## 화면

왼쪽 사이드바에 **대시보드 · 자산 · 입력** 메뉴, 총자산(억 단위), 데이터 파일 상태
(폴더 이름 · 저장 시각)가 있습니다. 앱 제목 색은 코스피 등락을 따릅니다 (상승 빨강 · 하락 파랑).
휴대폰에서는 사이드바 대신 상단바와 아래 탭이 나옵니다 — [휴대폰 화면](#휴대폰-화면).

### 휴대폰 화면

폭이 760px 이하(휴대폰)면 사이드바 대신 **위에 상단바, 아래에 탭**이 나오고, 대시보드 위쪽이 휴대폰용 카드로 바뀝니다.
숫자는 PC 대시보드와 같은 계산(소유자별 보기 포함)이라 같은 데이터면 같은 값이 나옵니다. PC 화면은 그대로입니다.

- **상단바**: 앱 아이콘 + 자산관리(누르면 홈 · 맨 위로, 제목처럼 코스피 등락 색) · **종**(챙길 알림이 있으면 빨간 점) · **해 / 달**(밝게 ↔ 어둡게)
- **인사말**: 시간대에 맞는 인사와, 최근 1개월 순자산이 늘었는지에 따라 바뀌는 한 줄
- **순자산 카드**: 금액(카운트업) · 최근 1개월 증감과 추세선(PC 순자산 카드의 "최근 1개월"과 같은 기준) · 목표 달성률 막대(누르면 목표 자산 설정 창).
  **눈 아이콘**을 누르면 휴대폰 카드의 금액을 흐리게 가립니다 (이 브라우저에 기억)
- **자산 구성**: 도넛 + 그룹별 금액 · 비율 (PC 자산 구성 카드와 같은 계산 — 연동 부채는 그 그룹에서 차감)
- **이번 달 자산 변화**: 지난달 말 대비 그룹별 증감 (부채가 줄면 "대출 상환" +), 합계 = 이번 달 순자산 증감. 누르면 이번 달 요약
- 그 아래로 순자산 추이 · 미래 자산 예상 · 월간 요약 · 공포 · 탐욕 지수 · 기록 잔디가 이어집니다
- **자산 탭**: 부동산 · 증권 · 예금 · 장기가 그룹마다 카드로 나뉘고, 항목을 누르면 상세(금액 · 차트 · 날짜별 기록 · 정보 수정)가
  **아래에서 올라오는 창**으로 열립니다 (✕ · 손잡이 · 바깥을 눌러 닫기). 날짜별 기록은 날짜 · 금액 · 증감이 겹치지 않게 맞추고,
  화면이 아주 좁으면 증감을 금액 아래로 내립니다
- **아래 탭**: 홈 · 자산 · **＋**(오늘 금액 입력 / 새 자산 추가) · 투자(연금 리밸런싱) · 더보기
  (금액 입력 · 뱃지 · 탐험 · 연간 결산 · 사용법 · 설정, 소유자별 보기, 화면 테마, 데이터 저장소 상태)
- **알림(종)**: 저장하지 않은 입력 · 새 뱃지 · 리밸런싱 시점 · 저장소 문제 · 새 버전을 모아 보여 주고,
  이번 달 요약 · 지난달 결산 · 공포 · 탐욕 지수로 바로 갈 수 있습니다
- 휴대폰 브라우저는 PC 폴더에 저장할 수 없으니, PC와 같은 기록을 보려면 **설정 → 클라우드 연동**(Supabase · 구글 시트)을 쓰세요
  (데모 화면 배너의 **클라우드 연동** 버튼으로 바로 갑니다)
- 상단바 이름(`자산관리`)은 `index.html` 의 `id="mBrandT"` 한 곳에서 바꿉니다

### 대시보드

### 등산 지도 (3D)

뱃지 화면 맨 위 카드와 미래 자산 예상의 **등산 지도로 보기** 창에 three.js 로 그린 3D 산이 나옵니다.

- **산 한 판**: 옆면에 지층이 보이는 네모난 땅 가운데 큰 산이 목표입니다. 호숫가 들머리(출발 0원)에서 앞면을 지그재그로 올라
  정상까지 가는 등산로의 길이가 곧 목표 금액이라, 지금 순자산 자리에 등산객(모자 · 배낭 · 스틱)이 서 있습니다.
  지나온 길은 강조색에 빛이 흐르고, 남은 길은 점선입니다. 땅에는 종이 등산 지도처럼 등고선(4줄마다 굵은 계곡선)이 그어집니다.
- **깃발 · 정상**: 10%마다 돌탑 위 깃발 — 넘으면 초록(정상은 금빛)으로 바뀌고 넘어선 날짜가 붙습니다. 정상석에는 목표 금액이 새겨지고,
  정상 이름표에 도달 예상 시기가 나옵니다. 목표를 이루면 등산객이 정상에서 만세를 하고 금빛 반짝이가 맴돕니다.
  새 기록으로 순자산이 오르면 등산객이 그만큼 걸어 올라가고, 새로 넘은 깃발이 톡 튑니다.
- **조작**: 끌기 = 돌리기 · 오른쪽 버튼(또는 `Shift`) 끌기 = 옮기기 · 휠 = 확대(뱃지 화면에서는 `Ctrl` + 휠, 그냥 휠은 화면 스크롤) ·
  두 번 누르면 그곳으로. 캔버스를 누른 뒤 방향키 · `+` `−` · `0`(처음 보기)도 됩니다. 깃발 · 등산객 · 정상석(또는 그 이름표)을 누르면
  가까이 가고, 깃발은 목표의 몇 % · 넘어선 날짜(아직이면 남은 금액)를 보여 줍니다. 이름표는 겹치거나 산에 가리면 숨습니다.
- **오른쪽 위 도구**: 처음 보기 · 내 위치 · 정상 · **지도 보기**(위에서 내려다본 등고선 지도 — 높이별 색, 남은 길은 빨간 점선) ·
  **지난 발자취**(첫 기록부터 오늘까지 기록한 순자산을 따라 등산객이 오르내리고, 넘는 깃발이 하나씩 초록으로 바뀜 — 왼쪽 위에 날짜 · 금액) · 확대 · 축소.
- **풍경**: 이 PC 의 날짜로 계절이 바뀝니다 — 봄 벚꽃, 여름 신록, 가을 단풍, 겨울 눈(눈 덮인 봉우리 · 눈 쌓인 소나무).
  어둡게 테마에서는 달밤이 되고 등산객이 헤드랜턴을 켭니다.
- 헤더의 **3D / 평면**으로 한 장짜리 그림 지도(예전 모양)와 바꿔 볼 수 있고, 고른 것은 기억합니다.
  WebGL 을 쓸 수 없는 브라우저에서는 자동으로 평면 지도가 나옵니다.
- **가볍게**: Three.js 는 탐험(자산마을)에 이미 들어 있는 r160 을 등산 지도를 처음 볼 때 꺼내 쓰므로 인터넷이 필요 없고, 파일도 여전히
  `index.html` 하나입니다. 지도가 안 보이면(다른 메뉴 · 스크롤로 벗어남 · 창 최소화) 그리기를 멈추고, 한동안 손대지 않으면 덜 자주 그리며,
  너무 느리면 해상도 · 그림자를 스스로 낮춥니다. 윈도우의 "애니메이션 효과 줄이기"를 켜 두면 움직임 없이 필요할 때만 그립니다.

| 대출이 **천만원 단위로 줄 때** / **부채 0원** | 🌸 꽃가루 / 🎆 폭죽 |

    "연금 리밸런싱 화면 열기". 비중에 필요한 전일 종가는 탐험을 열 때 불러 둡니다.
  - **상환 버스**(상환 정류장 옆 길): 부채가 가장 많았던 날이 출발, 부채 0 이 종점 — 갚은 비율만큼 버스가 앞으로.
  - **마을 성장**: 순자산 1억 꽃 화분 · 3억 2단 분수 · 5억 돛단배 · 10억 열기구 · 20억 동쪽 앞바다 바위섬의 등대(밤에 불빛). 왼쪽 목록의 "마을 성장"에서 다음 단계.
  - **주민 소식**: 동물 주민을 만날 때마다(창에 "🐻 신문 배달부 ○○님이 전하는" 처럼) 우리 집 소식(이번 달 증감 · 효자 자산 · 목표 예상 · 기록 알림 · 연속 기록 · 상환 버스 · 코스피)과
    네이버 증권 속보를 번갈아 하나씩 전합니다. 연금 리밸런싱 시점이면 모든 주민이 그것부터 알려 줍니다.
- **뱃지 기념물** — 뱃지 화면의 마일스톤이 마을에 세워집니다 (소유자 필터와 상관없이 전체 기록):
  억 돌파 → 광장 북동쪽 **석탑**(억마다 한 층) · 천만 돌파 / 신기록 → 광장 바닥 **별**(금빛 / 흰빛) ·
  목표 10% · 달성 → 상환 정류장 옆 **목표 언덕** 깃발(정상 = 달성, 금빛 표시 = 지금 위치) ·
  대출 감소 → 정류장 뒤 **도장 게시판**, 부채 0 → 정류장 위 **무지개** · 하루 기록 / 연속 기록 → 금고 산책길 앞 **꽃밭**(작은 꽃 / 해바라기,
  아직 뱃지가 없으면 새싹 — 옆에서 `F` 로 물 주기).
  금빛 이름표나 기념물을 누르면 받은 뱃지 목록이 열리고, 뱃지를 누르면 그때의 축하를 다시 봅니다.
- **실감 나는 풍경** — 해의 위치에 맞춰 낮 · 노을 · 밤 빛깔이 바뀌는 하늘과 그 하늘로 만든 주변광, 하늘과 마을이 비치는 호수 ·
  잔물결 바다, 코드로 그린 재질(잔디 · 돌길 · 회벽 · 기와 · 나무결 · 창유리), 가림 그늘(GTAO) · 빛 번짐 · 전체 보기의 미니어처 초점 ·
  색 보정, 바람에 흔들리는 나무와 풀밭, 계절 입자(봄 꽃잎 · 가을 낙엽 · 여름밤 반딧불) · 나비 · 새 떼.
  주인공과 동물 주민은 관절(엉덩이 · 무릎 · 어깨 · 팔꿈치)이 있는 몸으로 걷고, 주민 넷은 큰길을 오가며 끝에서 돌아섭니다.
  프레임이 느리면 효과를 한 단계씩 스스로 줄이고(가림 그늘 → 빛 번짐 · 물 반사), **가벼운 모드**는 예전 화면 그대로입니다.
  효과 모듈은 Three.js r160 예제(EffectComposer · GTAOPass · UnrealBloomPass · OutputPass · Sky · Water, MIT)를 함께 넣었습니다.
- 소유자는 목록 순서대로 첫 번째가 남자, 두 번째가 여자 캐릭터로 걷습니다.
- 날씨는 공포 · 탐욕 지수, 마을 주민은 네이버 증권 속보를 전합니다 (인터넷 연결 필요). 3D 화면이라
  브라우저의 하드웨어 가속이 켜져 있어야 하고, 다른 메뉴로 가면 그리기를 멈춥니다.
- 마을 앱 원본은 `index.html` 맨 끝 `<script type="text/plain" id="villageSrc">` 에 통째로 들어 있어
  (Three.js r160 · MIT 포함) 여전히 `index.html` 한 파일로 동작합니다. 처음 탐험을 열 때 iframe 으로 띄웁니다.
  3D 등산 지도도 이 안의 Three.js 를 꺼내 씁니다 — 원본을 통째로 바꿀 때 Three.js 블록이 빠지면 등산 지도는 평면으로 보입니다.

### 연금 리밸런싱

사이드바 탐험 아래(가로선 다음)의 **연금 리밸런싱** 메뉴(`6` 키)는
[pension-etf-rebalancer](https://github.com/iontiger/pension-etf-rebalancer)를 넓은 PC 화면에 맞게 다시 만든 것입니다.
계산 방식(정적 리밸런싱 · 신규 투입 배분)은 원본과 같고, 가격(전일 종가)과 차트 데이터는
원본 저장소가 매일 올리는 `prices.json` · `history/{종목코드}.json` 을 읽습니다 (인터넷 연결 필요).

| 탭 | 내용 |
|---|---|
| **리밸런싱** | 총자산(1달 추이 · 누르면 기간별 차트) · 최대 이탈 · 예수금 · 다음 리밸런싱 카드, 현재/목표 비중 막대, 보유 종목 표(행을 누르면 가격 차트) — 오른쪽에 **이번 계획**(추가 투입금 포함, 1단계 매도 → 2단계 매수)이 항상 보이고, 거래 후 **거래 완료 → 보유수량 반영** |
| **신규 투입** | 금액(빠른 버튼 +100만 ~ +1,000만)을 목표비중대로 나눈 종목별 매수 수량, 남는 돈으로 1주씩 더 사기, **매수 완료 → 보유수량 반영** |
| **종목 · 설정** | ETF 검색(이름·코드, `↑` `↓` `Enter`)으로 추가, 목표비중 · 보유수량 · 예수금, 밴드 · 최소 거래금액 · 주기, 알림(.ics) · JSON 내보내기/가져오기 · 초기화 — **저장**(`Ctrl+S`)해야 반영 |
| **기록** | 리밸런싱 · 신규 투입 기록 (최대 200건) |

- 주기가 지나면 왼쪽 메뉴에 빨간 **!** 가 붙습니다 (살짝 맥박치듯 깜빡임).
- **데모 모드**(데이터 폴더 연결 전)에서는 데모 포트폴리오가 나옵니다 — 3월에 3,000만원으로 시작해 매달 100만원씩 넣고 8월에 리밸런싱한 기록(실제 종가 기준)이라 총자산 추이 · 기록 · 계획을 바로 둘러볼 수 있습니다. 데모에서 반영한 것은 새로고침하면 사라지고, 원래 리밸런서 페이지의 기록도 건드리지 않습니다.
- 포트폴리오는 데이터 파일의 `pension` 항목에 함께 저장됩니다 (종목 · 기록은 한 줄에 하나씩).
  처음 열 때는 원래 리밸런서 페이지에서 쓰던 포트폴리오(같은 브라우저 · `iontiger.github.io`)를 그대로 가져오고,
  저장할 때마다 그쪽에도 똑같이 적어 두 페이지가 같은 값을 봅니다.

## 로고

데이터 폴더 안에 `logos` 폴더를 만들고 이미지(png · jpg · webp · svg · gif)를 넣으면
로고 선택 창에 바로 나옵니다 — 예전처럼 `logos.json` 목록을 만들 필요가 없습니다.
로고 선택 창의 **＋ 이미지 추가** 로 PC의 이미지를 골라 `logos` 폴더에 복사할 수도 있습니다.

- 데이터에 로고를 적을 때 확장자는 생략해도 됩니다 (`parkrio2` → `parkrio2.png`, `.jpg` … 자동 탐색)
- 데이터 폴더에 없는 로고는 `index.html` 옆 `logos/` 폴더에서 찾습니다
- **웹 주소(GitHub Pages)로 쓸 때**: 이 저장소의 `logos/` 폴더에 이미지를 올리고 푸시하면
  함께 배포되고, 로고 선택 창이 읽는 `logos.json` 목록도 배포 때 자동으로 만들어집니다
  (GitHub 웹에서 `logos` 폴더 → **Add file → Upload files** 로 올려도 됩니다)
